BioOrigin

Tracing evidence ancestry and quantifying error propagation in public biological databases

Abstract. Biological databases such as UniProt contain millions of protein annotations, many of which are inferred from other annotations rather than experimentally verified. When an upstream source is retracted, downstream entries silently inherit the error. This project presents BioOrigin, a client-side web tool that classifies every feature in a UniProt entry by its evidence tier, queries Crossref's retraction database for every cited PubMed record, and computes the "blast radius" — the number of other proteins that cite the same retracted source. The tool runs entirely in the browser using public REST APIs (UniProt, NCBI E-utilities, Crossref), requiring no backend infrastructure. It exposes evidence quality and inherited contamination that are invisible in existing database interfaces.

1. The Problem

Modern bioinformatics rests on a layered infrastructure of annotated databases: UniProt, PDB, Ensembl, RefSeq. Each annotation carries a provenance signal — an evidence code describing how a claim is known. UniProt's ECO taxonomy distinguishes experimental evidence (ECO:0000269) from curator inference (ECO:0000305), similarity-based inference (ECO:0000250), and fully automated annotation (ECO:0000313).

This architecture is remarkably principled. It is also incomplete. Three problems recur:

  1. Evidence chains are not exposed. A user sees that a feature is "inferred by similarity" but cannot tell which protein it was inferred from, or whether that source was ever verified.
  2. Retraction status is invisible. When a paper is retracted, UniProt does not remove or flag the annotations derived from it. The affected proteins continue to display their inherited features without warning.
  3. Propagation is unmeasured. No public tool reports how many entries a single bad source contaminates. This is the difference between "one paper was wrong" and "47 proteins depend on that wrong paper."

2. Method

2.1 Data sources

  • UniProt REST API — protein records, feature annotations, evidence codes, and cross-references. No authentication required.
  • NCBI E-utilities — PubMed metadata lookup (title, journal, DOI) for each PMID cited in a UniProt record.
  • Crossref REST API — retraction detection via the update-to field, which is populated from the Retraction Watch database.

2.2 Evidence classification

Each feature in a UniProt record is assigned a trust tier using a three-rule cascade:

  1. If an ECO code is present, map it to a tier (high / medium / low / very_low). When multiple codes apply, the weakest code determines the tier.
  2. If no ECO code is present but the feature type is structural (Helix, Beta strand, Turn), classify as high — these originate from solved PDB structures.
  3. If no ECO code is present but the source is a trusted database (PDB, PROSITE, Pfam, RefSeq, Ensembl), classify as medium.

Rule 2 exists because UniProt does not attach ECO codes to secondary-structure features, yet these are among the most reliable annotations in the database. A naive ECO-only classifier would misclassify them as unknown.

2.3 Retraction detection

For every cited PubMed ID, the tool fetches the paper's DOI from NCBI and queries Crossref for the presence of a update-to record of type retraction. Results are memoized per page-load to respect rate limits (10 req/s with an NCBI API key).

2.4 Impact analysis

When a retracted source is found, the tool issues a UniProt search of the form xref:pubmed-PMID, which returns every protein whose cross-references cite that paper. The count is reported as the blast radius of the retraction.

3. Findings

Selected results from representative UniProt entries examined during development:

98% of annotated features in rabbit mitochondrial aspartate aminotransferase (P12345) are classified as "inferred by similarity" — not experimental.
~50 structural features in human aromatase (P11511) carry no ECO code, yet originate from PDB crystal structures — misclassified as "unknown" by naive ECO-only classifiers.
0% of bacterial entries tested (E. coli, Salmonella, Haemophilus) carry ECO codes on their feature annotations — evidence coverage is organism-dependent.
100% of retracted sources, when present, propagate through every annotation that cites them. UniProt does not currently flag this.

4. Future Work

  • Backend cache with Turso. Store pre-computed classification per UniProt release, enabling instant lookups and differential queries between versions.
  • Full-database retraction scan. Run the retraction detector against every human-reviewed (Swiss-Prot) entry and publish the list of contaminated proteins.
  • Inference graph reconstruction. Fetch the entire "by similarity" graph for a protein family and compute transitive error propagation depth.
  • Preprint and trial retractions. Extend detection to bioRxiv withdrawals and ClinicalTrials.gov results retractions.
  • Integration with PDB. Detect retracted structures that were deposited based on retracted papers.

5. Tech Stack

Vanilla HTML, CSS, and JavaScript. No build step, no framework, no server. Deployed on GitHub Pages. All communication with public REST APIs is performed client-side via fetch().
